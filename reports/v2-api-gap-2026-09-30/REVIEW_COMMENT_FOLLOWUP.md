# V2 API design review comment follow-up

This companion to the [gap report](REPORT.md) checks whether Damian Kosowski's review comments on [PR #2277](https://github.com/roboflow/inference/pull/2277) were incorporated into subsequent design commits and into `feat/new-model-manager`. Several ideas were incorporated into the design, particularly the classification changes, while the implementation still differs. The final two columns record the direction and strength of support expressed in the subsequent team discussion.

## Scope and chronology

The three reviews were submitted on 27–28 April 2026. The subsequent design changes landed on 19 May 2026. This assessment compares the original design at `a7ef0df05` with the current PR head, `de634b98bac204c96caa98a15dd7559dded361d5`, including these relevant commits:

- [efa47b82e — Add chenges to model inference endpoint](https://github.com/roboflow/inference/commit/efa47b82e6a6a9001f3493c2f0550a07e72a0c3d): classification decisions, thresholds, request formats and response conventions.
- [11315f692 — Formalise ideas regarding interface discovery for models](https://github.com/roboflow/inference/commit/11315f6925850a45ff151107882ca71e4c6e7392): DELETE unload, explicit loaded-model route and interface discovery.
- [de634b98b — Polish the content with Claude](https://github.com/roboflow/inference/commit/de634b98bac204c96caa98a15dd7559dded361d5): further explanation and example changes, including multi-label thresholds and dense-output transport.

On 30 September 2026, all 14 inline review threads were still unresolved, 13 were marked outdated, and none contained a reply. GitHub's outdated marker records a changed diff location; it does not establish that the concern was addressed. The assessments below are based on the subsequent diffs and final document content, not inferred author intent.

## Decision status and discussion source

The direction/status columns reflect [Paweł’s reply][direction-reply] on **30 September 2026 at 17:48 CEST** in the [Slack thread][direction-thread]. At this snapshot, the thread contains Damian’s request for clarification and one reply from Paweł. These columns record current guidance, not final team agreement or completed implementation. A supported direction can still have open scope or contract details.

- **Supported:** Paweł explicitly endorses the direction. Confidence is high in that endorsement, not in every implementation detail or wider team consensus.
- **Tentative:** conditional wording, a preference, or a clearly labeled interpretation that needs confirmation.
- **Follow-up proposed:** positive direction with a proposed deferral; scheduling and scope are not settled.
- **Open:** no decision, an explicit request for discussion, or an unanswered detail.

When the thread develops, update the affected direction/status cells and their reply links, and advance this discussion snapshot date. Use **Agreed** only when the thread explicitly settles the relevant choice; do not promote a status because code exists or a GitHub thread is marked resolved. Keep design incorporation, implementation coverage, and decision confidence separate.

## Comment assessment

The implementation column is pinned to `3d45b8712cc428eb01b714f3609346be7c92acc4`, confirmed as the remote `feat/new-model-manager` tip on 30 September 2026. It assesses the public V2 HTTP path and relevant model code by source inspection, supported where applicable by the existing [audit observations](observations.json). It does not claim that an implementation was caused by the review comment. No new runtime tests were run for this column; the [validation record](VALIDATION.md) describes the earlier checks and limitations.

## Suggested follow-up

Use the direction/status columns to separate supported implementation work from decisions that still need discussion. In particular, do not resolve classification naming solely because the design adopted it: Paweł has explicitly reopened its value for discussion. Confirm tentative choices and missing contract details in the linked Slack thread, then reconcile the design and implementation findings. This document does not change any GitHub thread state.
