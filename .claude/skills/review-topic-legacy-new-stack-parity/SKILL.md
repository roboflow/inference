# Reviewing legacy → new-stack parity

## Scope
`inference_server/` (FastAPI layer) and `inference_model_manager/` (model lifecycle) replace `inference/core/interfaces/http/http_api.py` and `inference/core/managers/**`. They import nothing from `inference`: `inference_server/docker/Dockerfile.cpu` copies only `inference_models`, `inference_model_manager`, `inference_server`, `workflows`, `stream_vision` and the built landing page. Every legacy behaviour was re-implemented by hand, so a change in the legacy tree never propagates — it has to be re-applied in the counterpart in the same PR or the two servers silently diverge.

Load this skill when the PR touches any legacy path in the counterpart map. It owns one rule: a legacy change whose behaviour the new stack re-implements lands in both trees, and the review states which legacy hunks were checked and what was found.

OUT of scope: the quality of the counterpart code itself (generic review plus topic skills, INDEX §3); model implementations under `inference/models/**`, whose twin is `inference_models/**` (`review-inference-models-pkg`) — see the single FLAG below.

## Review procedure
1. For every changed hunk under a legacy path in the map, list the identifiers it introduces or changes: route literal, query/body parameter, response field or alias, status code, error message, header name, env var name or default, model-type / task-type string, lifecycle rule (eviction, pinning, preload, timeout), URL/image rule, usage row field.
2. Grep each identifier in the mirror files under `review-source/` (the PR tree). Outcomes: **mirrored** (a mirror file is in the diff and carries the change), **already present** (the base tree already behaves the same — cite file:line), **absent**.
3. For **absent**: check the "not (yet) available" list in `inference_server/README.md` and, for env names, the legacy-only section of `inference_server/docs/legacy_env.md`. Listed → never BLOCK; FLAG when the PR widens the documented gap without updating the list. Not listed → BLOCK.
4. For **mirrored**: confirm a test exercises the mirror — `inference_server/tests/**` or `inference_model_manager/tests/**` (run by `.github/workflows/unit_tests_inference_model_manager_and_server.yml`), or a black-box case in `tests/inference/integration_tests/**`, which runs unchanged against the new image (`.github/workflows/integration_tests_inference_server_x86.yml` with `server-image: new`; the new stack's expectation files are the `*_inference_models.json` siblings).
5. Whenever this skill loads and a review summary is posted, the summary carries one parity line: `Legacy→new-stack parity: <n> legacy hunks checked; mirrored: <files>; already present: <files>; not ported (documented): <items>; MISSING: <items>`. Never leave MISSING non-empty without a BLOCK finding.

## Review checklist
Severity-tagged. Resolve BLOCK before merge; raise FLAG; NIT is optional.

- **BLOCK** — An externally observable legacy change (route, parameter, field, status code, error text, header, env var or default, model-type dispatch, api-key resolution, usage row field, model lifecycle rule) has no mirror in the PR, the counterpart does not already behave the same, and the gap is not documented (step 3). Post inline on the legacy hunk, naming the mirror file and the identifier to add.
- **BLOCK** — A legacy bug fix covered by a test under `tests/inference/**` whose twin path in a mirror file shows the same defect and is left unfixed.
- **BLOCK** — A change to a request/response class under `inference/core/entities/**` without the same change in the counterpart the map names for it (`inference_server/inference_server/legacy/entities.py`, `inference_server/inference_server/workflows/workload.py`, or `inference_server/inference_server/legacy/translation.py` when the field is produced there).
- **BLOCK** — A new or renamed env var, or a changed default, in `inference/core/env.py` / `docker/config/*_http.py` with no row in `inference_server/docs/legacy_env.md` and no counterpart in `inference_server/inference_server/legacy_env.py` or the configuration modules when the new stack has the setting.
- **FLAG** — The mirror is present but no test in `inference_server/tests/**`, `inference_model_manager/tests/**` or `tests/inference/integration_tests/**` exercises it; or the legacy PR adds/changes an expectation JSON without the `*_inference_models.json` sibling.
- **FLAG** — The legacy change widens a gap listed under "not (yet) available" in `inference_server/README.md` and that list is not updated.
- **FLAG** — A fix in `inference/models/**` or `inference/core/models/**` whose `inference_models/**` twin shows the same defect; name the twin path (its review is owned by `review-inference-models-pkg`).
- **NIT** — Mirror differs only in log text or private naming.

### Not blocking
- Internal refactors with no observable change — but verify that by reading both trees (Zero-Trust Stance); the hunks still count in the parity line.
- Surfaces the README lists as not ported (WebRTC worker routes, `/sam3_3d/infer`, SAM3 remote embedding, `format=binary` on SAM routes, per-model colour map, per-model and per-workflow usage rows) — never BLOCK; FLAG per the checklist when the PR widens them without updating the list.
- The no-mirror paths listed under the counterpart map.
- A "will follow up in another PR" reply does not resolve a BLOCK (Zero-Trust Stance); only the mirrored code in this PR does. When the contributor cannot port the change, escalate per the prompt's Escalation rules instead of passing.
